## Right Now — Current State & Focus

**Workflow:** `main` is now Scout's single source of truth for development (deliberate change — see `CLAUDE.md`). New work happens on short-lived feature branches named `claude/**`, merges into `main` via pull request, and the branch is deleted afterward. CI (`.github/workflows/android-build.yml`) builds on every push to `main`/`claude/**`, runs the actual JVM unit test suite (`testDebugUnitTest`), not just a compile check, and also triggers on pull requests targeting `main`.

**Next step: real-device testing, not more coding.** Both structural bugs from the "Welcome back!" real-device report (PR #53, PR #55) are now merged. Before any further implementation: (1) boot Scout and say "Welcome back!" — confirm the short deterministic courtesy response, not an AI answer; (2) ask a deliberately slow generative question, let the Busy-Brain filler speak, confirm the real answer still follows correctly afterward; (3) keep watching for the intermittent TTS problem PR #52 instrumented (a reply displays but is sometimes never spoken) — **a likely root cause was found and fixed August 20 (PR #63: the caption `TextView` mutation in `speak()` could run on a TTS callback thread instead of the main thread, risking `CalledFromWrongThreadException`), but that PR is not yet merged, so keep watching until it lands and is confirmed on a real device** — if it recurs before then, pull PR #52's `DiagLog` "TTS" events for evidence instead of guessing; (4) keep observing presence/return greetings and Companion Moments during normal use. See Master Summary's "Current development phase" note in its August 16–19 entry for the full checklist.

**PR #53 merged.** `CourtesyIntent.WELCOME_BACK` (branch `claude/courtesy-welcome-back`, merge commit `ed5cf6c26d184a060d066a562f21064cfbf3f09a`) — a real-device gap where "Welcome back!" said to Scout's own boot greeting had no deterministic route and reached Gemini/TinyLlama like an open question. Deterministic, narrowly exact-matched — not a loose substring route; adversarial regressions confirmed ("welcome back to the show" stays unmatched). 57/57 tests pass locally, CI green.

**PR #55 merged.** `pendingAiAnswer` lifecycle fix — the Busy-Brain answer-holding slot previously had no expiry and no relevance check, so a stale queued answer could drain onto any later, fully unrelated Scout remark (a presence/return greeting, a Companion Moment) with a misleading "and about your earlier question" prefix. New `ScoutPendingAnswerGate` pure decision helper (`NONE`/`DELIVER`/`HOLD`/`EXPIRED`, expiry checked *before* hold), a 30s standalone expiry constant (`PENDING_AI_ANSWER_MAX_AGE_MS`), a presence-completion guard, supersede-on-new-generative-request, explicit-close discard, one shared `clearPendingAiAnswer()` helper, and controlled `DiagLog.PendingAnswerDiscardReason` diagnostics (`EXPIRED`/`SUPERSEDED`/`CONVERSATION_CLOSED`, no speech text). The good Busy-Brain case (filler → answer resolves during it → drains right after, prefixed) is unaffected, verified by trace. See Master Summary's August 16–19 entry for the complete implementation detail.

**PR #60 merged.** Weather TODAY-routing fix — NWS labels same-day forecast periods "Today"/"Tonight," never a literal weekday name, so a same-day, future-tense-phrased question ("What's the weather going to be today?") could misroute into a weekday-name lookup that could never match, producing "I can only see about a week ahead...Thursday from here." New pure `ScoutWeatherQueryClassifier` fixes the routing; caching, location, NWS networking, and offline behavior untouched. 12 tests pass locally, CI green.

**PR #61 merged.** Busy-Brain generation-ownership invalidation — `ScoutBusyBrainState`'s `isPending`/`discardReason` used to be the only validity signal, shared globally: a stale generation A, discarded because a newer deterministic turn B superseded it, could become wrongly "valid" again the instant a still-later generation C began, because `tryBegin()` unconditionally reset `discardReason = null` for the whole class. Fixed with a RAM-only, monotonically increasing `currentGenerationId` — every async completion (Gemini and TinyLlama both; `ScoutLlamaController`'s own separate token untouched) now captures and checks its own id. 20 tests including an A→B→C→late-A race regression, CI green.

**PR #62 merged.** Scout Local Language Pack v1 — a small, fully bundled (`app/src/main/assets/datasets/language_pack.json`, zero runtime download) exact-match vocabulary extension for existing deterministic courtesy behavior, 29 curated variants across 5 categories (GREETING/ACKNOWLEDGE/CONFIRM/THANKS/GOODBYE). New pure `ScoutLanguagePack` (no `android.*`/`org.json`/`Context` imports — `MainActivity` owns the asset read + JSON decode, hands it a plain Kotlin structure) owns validation (a duplicate variant across or within categories is rejected, never resolved by first/last-wins), flattening, and exact lookup. A miss falls through to today's unchanged behavior. YES/NO deliberately excluded from v1 — no generic pending-yes/no mechanism exists yet to safely gate an approval/decline action on. 12 tests pass locally, CI green.

**PR #63 — implemented, CI green, NOT yet merged.** TTS caption UI-thread safety — `TextToSpeech.UtteranceProgressListener` callbacks aren't guaranteed to run on the main thread, but `speak()` (which mutates the closed-captions `TextView` directly) is called from both main-thread paths and those callback threads, risking `CalledFromWrongThreadException`. Fix wraps only the three-line caption-update body in `runOnUiThread{}` — the same marshaling pattern already used elsewhere in this file. Nothing else in `speak()` changes. Awaiting ChatGPT's review of the actual diff before merge — see "Known Issues" below.

## 3. Scout's Core Philosophy

Scout should feel: Calm. Thoughtful. Quietly alive. Emotionally subtle. Occasionally curious.
Scout should NOT feel: Excited. Scripted. Fake. Cartoonish. Hyperactive. Constantly praising.

**Stability > Features | Presence > Intelligence | Honest > Fake cheerful | Local-first > Cloud | Predictable > Flashy**
